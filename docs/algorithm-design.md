# Алгоритмы: реализация, визуализация и правила сравнения

Документ фиксирует не только алгоритмы, но и договорённости, от которых зависит корректность сравнения результатов: правило лексикографического порядка, стабильность, формат ключей и методику замеров.

## 1. Общие принципы

- Все пять алгоритмов реализованы самостоятельно; встроенные `Array.Sort`, `List.Sort`, `OrderBy` не используются для получения результата.
- Алгоритмы не ссылаются на Avalonia и не знают о View/ViewModel.
- Каждый алгоритм сообщает о ходе работы через `IStepSink<TStep>`.
- Счётчики сравнений/перестановок/перемещений/файловых операций ведёт контекст выполнения.
- Отмена проверяется в циклах и перед файловыми операциями.
- Пояснения формулируются по фактическому результату сравнения, а не по предполагаемому.

## 2. Odd-Even Sort

### 2.1. Идея

Сортировка чётно-нечётными перестановками — модификация пузырьковой сортировки. За один проход выполняются две фазы:

1. **Чётная**: сравниваются пары `(0,1), (2,3), (4,5), ...`.
2. **Нечётная**: сравниваются пары `(1,2), (3,4), (5,6), ...`.

Если левый элемент больше правого, они меняются местами. Фазы повторяются, пока в течение полного прохода (обе фазы) не произойдёт ни одной перестановки.

### 2.2. Реализация

```text
sweeps = 0
do
    swapped = false
    emit phase "Чётная фаза"
    for i = 0; i + 1 < n; i += 2
        compare(i, i+1)
        if a[i] > a[i+1]
            swap(i, i+1); swapped = true
    emit phase "Нечётная фаза"
    for i = 1; i + 1 < n; i += 2
        compare(i, i+1)
        if a[i] > a[i+1]
            swap(i, i+1); swapped = true
    sweeps++
while swapped
```

### 2.3. Корректность и завершение

- После каждой фазы большие элементы сдвигаются вправо, поэтому массив постепенно упорядочивается.
- Условие завершения — отсутствие перестановок в обеих фазах полного прохода. Если перестановок нет, каждая соседняя пара уже стоит в правильном порядке, а значит, массив отсортирован.
- Пустой массив и массив из одного элемента завершаются сразу: циклы сравнений не выполняются, испускается событие завершения.

### 2.4. Сложность и память

- Сравнения: `O(n²)` в худшем и среднем случае; для почти отсортированного массива — заметно меньше.
- Перестановки: `O(n²)` в худшем случае.
- Дополнительная память: `O(1)` (кроме массива и событий).
- Алгоритм устойчив (стабилен): равные элементы не меняются местами, так как обмен выполняется только при строгом `>`.

### 2.5. Визуализация

- Столбцы: обычный, сравниваемый, активный (обмен), уже проверенный.
- Таблица: индекс, значение, состояние, подсветка участников.
- Журнал: номер шага, тип «Сравнение»/«Перестановка»/«Фаза», индексы и значения.
- Пояснения: «Сравниваем числа 7 и 3. Левое больше правого, поэтому меняем их местами», «Пара уже стоит правильно», «Проход завершён: перестановок не было — массив отсортирован».
- Отдельно показывается номер прохода и фаза.

## 3. Tournament Sort

### 3.1. Идея

Строится полное бинарное дерево, листья которого соответствуют элементам массива. Каждый внутренний узел хранит **индекс победителя** — минимального элемента в своём поддереве. Корень даёт минимум всего массива.

Минимум переносится в результирующий массив, его лист помечается сентинелом `+∞` (элемент исключён), после чего обновляется только путь от этого листа до корня. Процесс повторяется `n` раз.

### 3.2. Реализация

- `leafCount` — минимальная степень двойки, не меньшая `n`.
- Дерево хранится в массиве `tree[1..2*leafCount-1]`, `tree[1]` — корень.
- Листья `leafCount..leafCount+n-1` содержат индексы исходных элементов; остальные — `-1` (сентинел).
- Внутренний узел `v` хранит индекс с минимальным значением среди победителей детей `2v` и `2v+1`; пустые дети считаются `+∞`.
- После извлечения победителя его лист становится неактивным (`+∞`), затем для каждого узла на пути к корню выполняется сравнение двух детей и запись нового победителя.
- Результат записывается в отдельный массив; исходный массив не переставляется.

### 3.3. Корректность и завершение

- Инвариант: для каждого узла хранимый индекс указывает на минимум в его поддереве. Построение снизу вверх устанавливает инвариант; обновление пути сохраняет его.
- Корень всегда содержит минимум среди активных элементов.
- Каждая итерация исключает ровно один элемент; после `n` итераций активных листьев нет, результат содержит все элементы в возрастающем порядке.
- Сентинел `+∞` не может быть выбран, пока есть активные элементы.

### 3.4. Сложность и память

- Построение: `O(n)` сравнений.
- Каждое извлечение: `O(log n)` сравнений и обновлений.
- Итого: `O(n log n)` сравнений.
- Дополнительная память: `O(n)` на дерево и `O(n)` на результат.
- Алгоритм не является устойчивым в общем случае; для демонстрации это не требуется, но это явно указано в карточке.

### 3.5. Визуализация

- Дерево рисуется по уровням; в узлах — индекс победителя и значение.
- Активный путь от корня к исключаемому листу выделяется цветом.
- Победитель корня подсвечивается; исключённый лист становится серым.
- Результат показывается отдельной полосой столбцов, заполняемой слева направо.
- Журнал: «Построено дерево», «Победитель — элемент с индексом 4 (значение 2)», «Элемент перенесён в результат», «Лист исключён», «Обновлён путь дерева», «Дерево перестроено».
- Таблица исходного массива показывает активные/исключённые элементы; таблица результата — заполненные позиции.

## 4. Gnome Sort

### 4.1. Идея

Гномья сортировка — устойчивый квадратичный алгоритм. Указатель движется по массиву вперёд, пока соседние элементы стоят правильно. При нарушении порядка текущий элемент меняется местами с предыдущим, а указатель возвращается на одну позицию назад.

### 4.2. Реализация

```text
position = 1
while position < n
    if position == 0
        position = 1
    if a[position-1] <= a[position]
        position++
    else
        swap(position-1, position)
        position--
```

- Сравниваются только соседние элементы.
- Перестановка выполняется только при строгом `>`.
- Равные элементы не меняются местами, поэтому порядок одинаковых значений сохраняется.
- Пустой массив и массив из одного элемента завершаются сразу.

### 4.3. События и визуализация

- `Position` — текущая позиция и значение.
- `Compare` — сравниваемая пара и фактический результат.
- `Swap` — реальная перестановка соседних элементов.
- В шапке визуализации показывается текущая позиция.
- В журнале отражаются сравнения, перестановки и переходы по позициям.
- Пояснения: «Числа расположены правильно, поэтому переходим дальше», «Возвращаемся на одну позицию назад…».

### 4.4. Статистика и сложность

- Сравнения: `O(n)` в лучшем случае, `O(n²)` в среднем и худшем.
- Фактические перестановки соседних элементов: до `O(n²)`.
- Перемещения в дополнительный массив: 0.
- Дополнительная память: `O(1)`.
- Устойчивость: да.

## 5. Merge Sort

### 5.1. Идея

Рекурсивная сортировка слиянием по принципу «разделяй и властвуй»:

1. Диапазон делится пополам.
2. Деление продолжается до отдельных элементов.
3. Отсортированные части сливаются через буфер.
4. При равенстве выбирается левый элемент — сортировка устойчива.
5. Буфер возвращается в массив.

### 5.2. События

- `Split` — разделение диапазона, границы левой и правой частей.
- `MergeLeaf` — диапазон из одного элемента уже отсортирован.
- `MergeStart` — начало слияния двух отсортированных частей.
- `Compare` — сравнение первых доступных элементов.
- `MergeSelect` — выбор элемента для буфера.
- `MergeWrite` — запись элемента в буфер.
- `MergeCopyBack` — возврат элемента из буфера в массив.
- `MergeComplete` — завершение слияния диапазона.

События содержат `RangeStart`, `RangeMid`, `RangeEnd` и снимок уровней `MergeLevelsSnapshot`. Это позволяет UI выделять текущие подмассивы, показывать буфер и строить уровни рекурсии без хранения полной копии массива на каждом шаге.

### 5.3. Визуализация

- Исходный массив и таблица обновляются по мере записи результата.
- Левая и правая сливаемые части подсвечиваются разными цветами.
- Сравниваемые элементы выделяются, выбранный элемент — активным цветом.
- Буфер слияния отображается отдельной диаграммой.
- Вкладка «Уровни слияния» показывает дерево диапазонов по уровням рекурсии: жёлтые — делятся, синие — сливаются, зелёные — уже отсортированы.
- Журнал различает разделение, сравнение, выбор, запись в буфер, возврат в массив и завершение слияния.

### 5.4. Статистика и сложность

- Сравнения: `O(n log n)`.
- Перемещения: каждая запись в буфер и каждый возврат в массив учитываются отдельно; перестановками они не считаются.
- Обмены (`Swaps`) для Merge Sort равны 0.
- Дополнительная память: `O(n)`.
- Время: `O(n log n)` во всех случаях.
- Устойчивость: да, при выборе левого элемента при равенстве.

## 6. Natural Merge Sort (внешняя сортировка)

### 4.1. Идея

Естественное слияние использует уже существующие упорядоченные участки (естественные серии). В отличие от прямого слияния, не нужно искусственно разбивать файл на фиксированные блоки: границы серий определяются по фактическому порядку ключей.

### 4.2. Файловый конвейер

```text
исходная таблица (CSV, память для отображения)
        │
        ▼
рабочий файл records.jsonl          ← исходный CSV не изменяется
        │  последовательное чтение, поиск серий
        ▼
run-0001.jsonl, run-0002.jsonl, ...  ← каждая серия в отдельном файле
        │  попарное слияние
        ▼
pass-1/run-0001.jsonl, ...           ← новые серии
        │  повторять, пока серий > 1
        ▼
result.jsonl ──► CSV пользователя (все исходные столбцы)
```

- Формат временных файлов — JSON Lines: одна запись на строку, поля сохраняются как массив строк. Это исключает конфликты с разделителями и кавычками внутри значений.
- Каждый файл серии читается последовательно; в памяти находятся только текущие записи буферов слияния.
- После успешного слияния входные файлы удаляются. Временный каталог удаляется в `finally`.
- Исходный пользовательский CSV только читается; результат пишется в отдельный файл.

### 4.3. Поиск серий

Запись считается продолжением серии, если её ключ не меньше предыдущего (для сортировки по возрастанию). Для убывания сравнение инвертируется, но при равенстве ключей сохраняется исходный порядок.

Алгоритм читает рабочий файл один раз:

1. Читает первую запись, открывает файл серии.
2. Для каждой следующей записи сравнивает ключ с предыдущим.
3. Если порядок нарушен — закрывает текущую серию, фиксирует её диапазон и открывает новую.
4. После конца файла закрывает последнюю серию.

Каждая серия описывается: номер, начало/конец (в исходной последовательности), количество записей, первый и последний ключ, список идентификаторов для предпросмотра.

### 4.4. Слияние

Для пары серий открываются два читателя. На каждом шаге:

- сравниваются текущие ключи;
- выбирается меньший (при равенстве — левый, что обеспечивает устойчивость);
- запись пишется в выходной файл;
- читается следующая запись из выбранной серии.

Если одна серия закончилась, остаток другой копируется без сравнений. Результат — новая серия. Серии, оставшиеся без пары, переносятся в следующий проход.

### 4.5. Сложность

- `R` — число естественных серий.
- Каждый проход читает и пишет `O(n)` записей.
- Число проходов — `O(log R)`.
- Итого: `O(n log R)` сравнений и файлового ввода-вывода.
- Память: `O(1)` записей на буферы плюс одна запись на серию для метаданных; таблица в UI хранится отдельно для отображения.
- Устойчивость: да, за счёт выбора левой записи при равенстве и сохранения порядка внутри серий.

### 4.6. Ключи и пустые значения

- Тип ключа: строка, целое число, вещественное число.
- Строки сравниваются `InvariantCultureIgnoreCase` — без зависимости от локали машины, с разумной обработкой регистра.
- Числа разбираются в инвариантной культуре; для вещественных допускается и точка, и запятая как десятичный разделитель.
- Пустое значение считается меньшим любого непустого; при сортировке по убыванию пустые значения оказываются в конце.
- Некорректное число в числовом столбце — ошибка с указанием строки; пользователь видит сообщение, сортировка не начинается.
- При равных ключах исходный порядок записей сохраняется.

### 4.7. Визуализация

- Полная таблица исходных записей с прокруткой.
- Полоса серий: цветные сегменты, номера, границы, количество записей.
- Панель текущего слияния: левая и правая серии, сравниваемые ключи, выбранная запись.
- Таблица результата прохода, пополняемая по мере записи.
- Журнал: поиск серий, сравнение, выбор, чтение, запись, завершение слияния/прохода.
- Пояснение: «Сравниваем ключи 12 345 и 9 876. Левое значение больше, поэтому следующей в результат пойдёт запись из правой серии».

## 7. QuickSort

### 5.1. Идея

Классическая быстрая сортировка с разбиением вокруг опорного элемента. Для устойчивости к дубликатам и плохим входам используется **3-way partition** (меньше / равно / больше) и **introsort**-защита.

### 5.2. Реализация

1. Для малых диапазонов (`<= 16`) — сортировка вставками.
2. Опорный элемент — медиана из первого, среднего и последнего элементов (median-of-three).
3. Разбиение на три группы: `< pivot`, `== pivot`, `> pivot`.
4. Рекурсивная обработка групп `<` и `>`.
5. Если глубина рекурсии превышает `2 * log2(n)`, диапазон сортируется собственной пирамидальной сортировкой (heap sort) — защита от сценариев, приводящих к `O(n²)`.
6. Сравнение строк — общий `StringComparer` с Radix Sort (см. раздел 8).

### 5.3. Сложность

- Среднее: `O(n log n)`.
- Худшее без защиты: `O(n²)`; с introsort-переходом на heapsort — `O(n log n)`.
- Дополнительная память: `O(log n)` на стек рекурсии.
- Устойчивость не гарантируется; для подсчёта частот это не важно, так как равные слова неразличимы. Результат обоих алгоритмов сравнивается как последовательность строк.

## 8. Radix Sort

### 6.1. Идея

Поразрядная сортировка строк переменной длины. Используется **LSD** (least significant digit) по кодовым единицам UTF-16:

- каждый символ строки — разряд;
- строки дополняются виртуальным терминатором `0`, который меньше любого символа;
- проходы выполняются от последнего разряда к первому;
- на каждом проходе — устойчивая сортировка подсчётом по 65 537 значениям (`0..65535` + терминатор).

Это именно поразрядная сортировка, а не сортировка по заранее вычисленному ключу. Она поддерживает Unicode (включая суррогатные пары) и строки разной длины.

### 6.2. Почему UTF-16 и ординальный порядок

Правило сравнения для задания 3:

> После нормализации Unicode Form C и приведения к нижнему регистру `ToLowerInvariant` слова сравниваются лексикографически по кодовым единицам UTF-16. Если одна строка является префиксом другой, более короткая считается меньшей.

Это правило:

- одинаково для QuickSort и Radix Sort;
- не зависит от локали и платформы;
- точно соответствует поразрядной сортировке по `char`;
- поддерживает кириллицу, латиницу и другие письменности.

Особенность: порядок задаётся кодовыми единицами, а не национальным алфавитом (например, `ё` идёт по коду, а не строго после `е`). Это осознанное и документированное правило, а не расхождение между алгоритмами. Для демонстрационных словарей и типичных текстов результаты выглядят естественно.

### 6.3. Сложность

- `d` — максимальная длина слова (в кодовых единицах).
- `O(d * (n + 65536))` по времени; при типичных `d` и `n=5000` это быстро.
- Дополнительная память: `O(n + 65536)`.
- Устойчивость: да.

### 6.4. Нормализация слов

Оба алгоритма получают массив уже нормализованных слов из `TextTokenizer`:

- Unicode Normalization Form C;
- `ToLowerInvariant`;
- удаление пунктуации и лишних пробелов;
- сохранение букв и цифр;
- поддержка кириллицы и латиницы;
- повторяющиеся слова остаются в массиве.

## 9. Подсчёт частоты

После сортировки достаточно одного линейного прохода:

```text
current = words[0]; count = 1
for i = 1..n-1
    if words[i] == current: count++
    else: emit(current, count); current = words[i]; count = 1
emit(last, count)
```

Так как равные слова стоят рядом, дополнительные словари не нужны для получения порядка. Для поиска по таблице UI использует отдельную фильтрацию.

Дополнительно вычисляются:

- общее число слов;
- число уникальных слов;
- топ-5 по частоте (при равенстве — лексикографический порядок).

## 10. Генерация текста

- Встроенный словарь английских и русских слов.
- `Random(seed)` с явным seed для воспроизводимости.
- Случайные длины предложений, знаки препинания, переносы строк.
- Одинаковый seed и размер дают одинаковый текст.
- Для экспериментов используется один и тот же массив слов для обоих алгоритмов; копии создаются до запуска `Stopwatch`.

## 11. Методика экспериментов

1. Пользователь задаёт размеры (по умолчанию 100, 500, 1000, 2000, 5000; можно добавить свои).
2. Для каждого размера генерируется массив слов (вне замера).
3. Выполняется прогрев (один вызов каждого алгоритма, вне таблицы).
4. Выполняется `repeats` замеров (по умолчанию 5). Для каждого замера:
   - массив клонируется до запуска `Stopwatch`;
   - `Stopwatch.StartNew()`;
   - вызов `QuickSort`/`RadixSort`;
   - `Stopwatch.Stop()`;
   - результат проверяется на корректность (в отладочной сборке/тестах).
5. В таблицу попадает медиана замеров.
6. UI получает строки результатов и строит график.
7. Время генерации, копирования, нормализации, обновления таблицы и отрисовки в замер не входит.

График:

- две серии (QuickSort, Radix Sort);
- подписи осей «Количество слов» / «Время, мс»;
- легенда;
- логарифмическая шкала по Y, если разница значений велика; подпись шкалы;
- читаемые подписи и сетка.

## 12. Ограничения демонстрации

- Массив для визуализации: 1–200 элементов. Это ограничение UI, а не алгоритмов; большие массивы проверяются в тестах.
- Турнирное дерево читаемо до 32–64 листьев; для больших массивов оно масштабируется, но основная ценность — пошаговость.
- Внешняя сортировка демонстрируется на полном наборе стран (195 записей) или пользовательском файле; временные файлы реальные.
- Бенчмарки ограничены разумным временем; максимальный размер можно увеличить вручную.
